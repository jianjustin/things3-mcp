## 二、待补充功能（按 MCP 2026-07-28）

### 必须做：协议和 SDK 升级

> 状态：第 1、2、3、4、5、8、14 条已在 `feat/sdk-v2` 分支完成（`c008a56`）。用 stdio 实测过 2024-11-05 到 2026-07-28 共五个协议版本，真实写入的冒烟测试 19 项全部通过。还没做：第 6 条 outputSchema（要先修 P1-7 的日期格式）、第 7 条缺失的工具、第 9 到 13 条。第 14 条里的 icons 和 websiteUrl 也还没加。

1. **SDK 从 `@modelcontextprotocol/sdk@1.12.0` 升级到 v2（`@modelcontextprotocol/server@2.4.x`）**。v2 实现了 2026-07-28，同时兼容 2025 那一代协议的客户端。v1 只维护到 2027 年初左右。
2. **从低层 `Server` 迁到 `McpServer.registerTool`**（`Server` 类已经标了 `@deprecated`）。迁过去可以顺带解决几件事：
   - zod 入参校验，失败时自动返回 `isError`，解决 P1-16；
   - 未知工具自动返回 `-32602`，handler 抛的异常自动转 `isError`，这样手写的 `callTool` 就可以删掉；
   - `McpError` 在 v2 里改名为 `ProtocolError`。
3. **2026-07-28 的无状态协议**：支持 `server/discover`，每个结果带 `resultType` 和 `_meta.serverInfo`，列表结果带 `ttlMs`/`cacheScope`。这些主要由 SDK v2 处理，升级后需要验证。

### 工具定义

4. **annotations**：给 25 个工具都加上 `readOnlyHint`、`destructiveHint`、`idempotentHint`，`openWorldHint` 设为 `false`（只操作本地应用）。
   - 只读：`todos_list`、`todos_get`、`projects_list`、`projects_get`、`areas_list`、`tags_list`、`logbook_search`。
   - `destructiveHint: true`：四个 `*_delete`、`todos_update`、`projects_update`、`bulk_move`、`bulk_updateDates`、`tags_remove`。
   - 幂等：`todos_complete`、`todos_uncomplete`、`projects_complete`。
5. **顶层 `title`**：给每个工具一个人类可读的显示名。
6. **`outputSchema` + `structuredContent`**：读类工具返回有类型的结构化结果，同时保留 JSON 文本块。前提是先修 P1-7，让日期统一为 ISO 8601。
7. **补上缺失的工具**，按价值排序：
   - 读取 Today / Upcoming / Anytime / Someday 等内置列表（`todos_list` 的 filter 只覆盖了一部分）；
   - 清单项的读和写（`checklistItems` 目前只能写入）；
   - heading 的读取和创建；
   - 取消待办或项目（canceled 状态）；
   - 按 `areaId` 过滤的 `projects_list`、区域重命名、标签重命名或改父级；
   - 从废纸篓恢复、清空废纸篓（这两个应设为 destructive）。

### 其他服务器能力

8. **`instructions`**：在 discover 或 initialize 结果里说明 ID 的来源、日期格式和 auth token 的要求，帮助模型用对工具。
9. **Resources**：把列表做成只读资源，比如 `things://today`、`things://projects`、资源模板 `things://project/{id}`。声明 `listChanged`，并通过 `subscriptions/listen` 推送变更。
10. **Prompts**：每日规划、每周回顾、收件箱整理这类工作流模板。
11. **Completions**：给 prompt 和资源模板的 projectId、areaId、tag 参数提供自动补全。
12. **Progress 和 cancellation**：`bulk_*`、`logbook_search` 这类耗时操作发 `notifications/progress`，并响应 `notifications/cancelled`。
13. **Elicitation（form 模式）**：删除等破坏性操作前，以及缺少 auth token 时，向用户确认或索取，替代现在的静默失败。2026-07-28 起改为通过 MRTR 的 `inputRequired` 发起。
14. **serverInfo**：补全 `title`、`description`、`websiteUrl`、`icons`，并且版本号从 package.json 读取，不再写死。
15. **不要做**：Logging（`notifications/message`）和 Sampling 在 2026-07-28 已经标为 Deprecated。stdio 服务器继续把日志写到 stderr 就行。

## 三、冒烟测试观察到的 Things3 行为

- `projects_complete` 会把项目里所有未完成的待办一起标记完成，已写进工具描述。
- 不存在的标签会被 URL scheme 静默丢弃；现在会报错，并提示先用 `tags_create` 建标签。
- 已完成的条目无法用 AppleScript `delete` 删除（-1728），移到 `list id "TMTrashListSource"` 则可以。
- `list-id` 传空字符串，会把待办移回收件箱。
- `when=evening` 时开始日期是当天；`someday` 和 `anytime` 没有开始日期。
